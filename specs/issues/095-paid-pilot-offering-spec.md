# Issue 95 Spec: Paid Pilot Offering

## Problem

Nitely should not start with self-serve SaaS pricing. The first commercial
motion should sell a high-touch paid pilot that converts a customer's repeated
engineering work into production Nitely flows while keeping execution in the
customer environment.

## Goals

- Define a pilot one-pager for the first 3-5 teams.
- Make pricing, duration, included scope, exclusions, and success metrics
  explicit.
- Provide a reusable onboarding checklist.
- Define how pilot learnings feed future team-control-plane requirements.
- Keep the offer consistent with the open-core and customer-hosted runner
  boundary documents.

## Non-Goals

- Implement billing, subscriptions, invoices, or entitlement checks.
- Define self-serve pricing tiers.
- Promise hosted control-plane features that are not implemented.
- Replace customer discovery notes required by #92.

## Acceptance Criteria

- Pilot one-pager exists.
- Pilot pricing, scope, and success metrics are explicit.
- A reusable onboarding checklist exists.
- Pilot learnings can feed team-control-plane requirements.
