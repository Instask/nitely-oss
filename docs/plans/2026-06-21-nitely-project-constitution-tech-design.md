# Nitely Project Constitution Tech Design

## Summary

Implement #102 by adding a small run-layer constitution loader and threading its optional result into prompt rendering and evidence generation. This creates the governance artifact needed by later structured spec, plan, task, and analysis issues without adding enforcement policy yet.

## Technical Context

- Runtime: TypeScript on Node 24.
- Current run orchestration lives in `src/run/run-flow.ts`.
- Run evidence is generated by `writeEvidence`.
- Agent/review prompts are rendered by `renderPrompt`.
- Redaction is already centralized through `redactRuntimeText`.

## Files / Modules Touched

- Create `src/run/constitution.ts`.
- Modify `src/run/run-flow.ts`.
- Add `test/run/constitution.test.ts`.
- Extend `test/run/run-flow.test.ts`.
- Add `docs/templates/nitely-constitution.md` as the starter template.
- Add this spec/design pair.

## Data / Schema Changes

No persisted database schema changes. Evidence gains a `## Constitution` section. Prompt content gains a `## Governing Principles` section only when a constitution is loaded.

## Flow / API / CLI Contract Changes

No CLI or Web API changes. Runs automatically detect `.nitely/constitution.md` in the target repo.

## Failure Modes And Recovery

- Missing file: no failure.
- Empty/whitespace file: no prompt injection; evidence records not loaded.
- Read failure other than missing file: degrade as not loaded for now, preserving existing run behavior.
- Secret content: existing redaction path applies before prompts/evidence are persisted.

## Compatibility / Migration

Existing repositories need no changes. Operators can copy `docs/templates/nitely-constitution.md` to `.nitely/constitution.md` when they want governance context loaded.

## Test Strategy

- Unit tests for missing, empty, and loaded constitution.
- Unit test for deterministic `sha256:` content hash.
- Run-flow integration test for prompt injection and evidence recording.
- Run-flow integration test that missing constitution keeps prompts unchanged and run completes.

## Constitution Check

This design supports the trust model by keeping the constitution repo-local and never uploading it. It preserves durable evidence and does not bypass human gates or existing flow validation.

## Complexity Justification

A separate `src/run/constitution.ts` module is justified because future #103/#105/#107 work will need the same loader/hash metadata outside prompt rendering. No new dependencies are introduced.
